# Rivet v0.1.0-alpha.1

Rivet's first alpha brings together Solo coding, optional multi-agent workflows and durable recovery in a Linux terminal application. It is intended for early testing and feedback.

Rivet runs independently of Unrivet. You choose an existing model provider; Rivet does not automatically download models, install an inference runtime or switch to a cloud service.

## What's included

### Coding and providers

- Solo coding with reviewed file changes, isolated process checks and selected local Git operations.
- Configuration, status and session administration without model credentials.
- Compatible Chat Completions, native Ollama and Anthropic provider profiles.
- Explicitly configured stdio MCP servers and content-pinned skills.

### Multi-agent workflows

- **Pair, Crew and Fleet:** reviewed task graphs, separate agent contexts, accountable task ownership and technical review tied to recorded changes and checks.
- **Mesh:** local peer agents with task ownership and conflict escalation.
- **Adaptive:** transitions between permitted compositions while preserving review, permission and budget constraints.
- **Shared Model, Concurrent and Relay:** bounded model-use policies with separate contexts and capacity reservations. External runtime activation remains manual.
- **Cookbook:** read-only recommendations from supported llmfit data and explicit whole-team allocations.

### Recovery and controls

- SQLite-backed task state, audit events, operation intents and evidence artifacts.
- Explicit reconciliation, backup and restore for interrupted work.
- Pause, stop, resume and opt-in detached execution under existing run limits.
- Permission checks, revision checks and recorded operation results throughout the workflow.

## Testing

The release-preparation contained test suite passed **77 tests with zero failures**. **Eight native tests were skipped** because they require separately authorized host systemd/cgroup access. Earlier native passes are recorded in the project evidence, but fresh release qualification remains outstanding.

Provider tests use synthetic streams. Live-model compatibility, coding quality and performance have not been qualified. These results cover the development source reviewed during preparation, not a final version-aligned alpha build.

## Known limitations

- **Experimental Linux source build:** the executable and workers are tied to the source checkout. Portable binaries, arbitrary external project roots and general installation support are not qualified.
- **Bounded autonomy:** task graphs and permissions are explicitly reviewed. Mesh is local; Adaptive does not create unrestricted agent trees. Declared model capacity is not a hardware measurement.
- **Qualification gaps:** fresh native tests, live-model checks, persistent keyring support, multi-day endurance and real reboot/power-loss testing remain outstanding. Rustfmt and Clippy were unavailable in the recorded environment.
- **Future features:** browser/desktop automation, Android testing, official mods, the global terminal dashboard, Resource Controller, Recycle Bin and broader memory/export designs are not included. macOS and Windows are not qualified.

Use a backed-up test project. Authorized tools and repair operations can modify files and state; cancellation does not undo completed actions. Remote inference sends approved context to the provider and may incur charges. Keep credentials out of configuration and reports.
