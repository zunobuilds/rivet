# Rivet v0.1.0-alpha.1

**Unpublished release-notes draft — experimental source preview.** Not production-ready. Publication is blocked by version alignment and outstanding qualification. No verified binary distribution is available.

This first planned pre-release presents Rivet's bounded Solo and multi-agent coding runtime for Linux. It works independently of Unrivet. No inference endpoint is selected by default, and no inference runtime or model weights are acquired automatically.

## Implemented

- Model-free configuration, status and session administration; explicit provider setup and bounded, reviewed Solo coding.
- Permission-controlled file operations, isolated process checks and selected local Git operations, with exact approvals, revision checks and durable receipts.
- Compatible Chat Completions, native Ollama and Anthropic profiles; explicitly configured stdio MCP and content-pinned skills. Provider conformance evidence is synthetic.
- SQLite-backed task/audit state, intent and artifact persistence, explicit repair/reconciliation, backup/restore, pause/stop/resume and opt-in detached execution.
- Reviewed Pair/Crew/Fleet graphs with separate contexts, fenced task ownership, evidence-bound technical review and consent-bound messaging.
- Shared Model/Concurrent/Relay policies with declared instance/context-cache capacity accounting, manual external-runtime activation and bounded read-only Cookbook recommendations.
- Local Mesh ownership/conflict handling and policy-bound Adaptive transitions at safe boundaries.

## Verification

The release-preparation contained suite passed **77 tests, zero failed, eight ignored** on the existing qualified environment. Locked offline Cargo metadata confirms the current package version is still `0.1.0`; it is not yet an alpha-version build.

The earlier post-P3 audit also recorded successful build/check, developer and build-script containment probes, 16 CLI/example invocations and checksums for 227 locked dependency archives. Those are historical results, not newly repeated checks on a final version-aligned release commit.

The eight ignored tests require separately authorized native systemd/cgroup access. Earlier P3 evidence records native passes, but fresh release-candidate qualification remains incomplete. No real model or paid endpoint was used; synthetic streams do not establish live model quality, interoperability, speed or physical capacity.

## Known limitations and warnings

- This is a checkout-bound Linux development build. Workers use the source checkout's debug executable path; portable binaries, arbitrary external project roots and a general installation procedure are unqualified.
- Native worker isolation, Git/Solo/MCP workflows, old-worker recovery, detached lifecycle and hierarchy checks need fresh native requalification. Missing enforcement must remain a refusal, not a sandbox bypass.
- No live-model qualification, persistent keyring backend, multi-day endurance, real reboot/power-loss evidence or broad platform certification. Rustfmt/Clippy were unavailable in the recorded environment.
- Plans are explicitly reviewed and bounded. Adaptive does not invent unrestricted task trees; Mesh is local, not a distributed cluster. Capacity/residency declarations are owner inputs, not measurements.
- Runtime state, revisions and files may change during authorized coding/repair. Preserve backups and recovery evidence; cancellation cannot undo completed effects or guarantee provider billing stopped.
- Remote inference transfers approved context and can incur charges. Use explicit destination/data/spend limits. Do not put credentials in configuration, reports or commands.
- Browser/native desktop automation, Android testing, official mods, the hybrid global UI, shared Resource Controller, Recycle Bin and broader memory/export designs remain future work. macOS and Windows are not qualified.
