# Rivet v0.1.0-alpha.2

This pre-release corrects the package-version mismatch in the first alpha. Rivet's coding features and runtime behavior are unchanged.

## Changes since alpha.1

- **Consistent package version:** Cargo.toml and the root Cargo.lock entry now use `0.1.0-alpha.2`. The published `v0.1.0-alpha.1` tag contains package version `0.1.0`; that tag and its archives remain unchanged.
- **Version-aware dependency audit:** the audit script reads Rivet's version from Cargo.toml instead of hard-coding it.
- **Updated release documentation:** records the published alpha.1 status, version discrepancy and remaining qualification work.

No dependency versions changed. There are no new agent modes, providers or tools in this update.

## Verification

Cargo metadata confirms `0.1.0-alpha.2` in the manifest and lockfile. A parsed lockfile comparison verified that only Rivet's root version changed during the alpha.2 bump.

The preceding alpha.1 package-correction build passed **77 tests, zero failed, eight native tests skipped**, and verified all **227** locked dependency archives. Those results belong to that earlier build. A full alpha.2 build, CLI-version check and test run remain pending before publication.

Fresh native qualification and live-model testing are still outstanding. Synthetic provider tests do not establish live-model compatibility, coding quality or performance.

## Known limitations

Rivet remains an experimental Linux source build tied to its checkout. Portable binaries, general installation support and arbitrary external project roots are not qualified. No verified binaries are supplied with these notes.

The [alpha.1 notes](https://github.com/zunobuilds/rivet/blob/main/docs/releases/v0.1.0-alpha.1.md) describe the existing Solo, multi-agent, provider and recovery features. Their limitations still apply, including manual external-model activation and unqualified keyring, endurance, reboot and power-loss behavior. Browser/desktop automation and the other roadmap features remain future work.

Use a backed-up test project. Tools can modify files, and remote inference can transfer approved context and incur charges. Rivet does not automatically acquire models or inference runtimes.

See the [build guide](https://github.com/zunobuilds/rivet/blob/main/docs/building.md) and [release checklist](https://github.com/zunobuilds/rivet/blob/main/docs/release-readiness.md) for setup and outstanding checks.
