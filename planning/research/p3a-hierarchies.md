# P3a hierarchy qualification

30 October 2026. Prerequisites: P2a `354cf6c` and P2b `4aad777`, with the [bounded qualification contract](../P2_P3_QUALIFICATION.md). This is synthetic-provider and current-host native evidence, not live-model quality or endurance qualification.

## Implemented profile

Schema 6 adds one persisted typed task graph, fenced per-quantum claims, inference assignments, messages and forwarding consents to the existing ledger/writer. Approved counts are enforced: Solo 1 Independent; Pair 1 Lead + 1 Operator; Crew 1 Lead + 1 Reviewer + Operators >=1; Fleet 1 Director + Leads/Reviewers/Operators >=1. Initial ceiling: 32 actors, 256 tasks, a 64 KiB reviewed input plan and 512 KiB bounded graph record. Minimal validation permits only Solo. Skills attach to existing actors without adding roles; enabled content pins and brokered reads remain mandatory.

`run template --mode pair --task TEXT` produces a reusable JSON plan. `--paths PATH` declares coding paths; Crew/Fleet templates require checked paths. `run hierarchy --plan PATH` previews the exact input; `--approve DIGEST` admits it, with fresh per-run IDs and recorded initial recipient/task scopes. The API also provides an explicit admission review. There is no model authority to invent roles, expand paths or mutate a live task definition. Coordinators plan/integrate the reviewed graph; Operators use the common reviewed tools; Reviewers return strict technical decisions about exact recorded evidence. These decisions never authorize a tool.

The same supervisor, broker, registry, lifecycle, aggregate budgets and worker containment execute every role. Each quantum is one provider or tool step. FIFO queues per parent receive round-robin service. Writer leases cover overlapping path prefixes and Git metadata; a fully observed quantum can release its lease, avoiding FIFO deadlock. Unknown work retains its fence and blocks affected completion. Expiry alone never permits another owner; explicit post-containment recovery evidence is required to reconcile a lost claim. Old claims, permission epochs and grants cannot dispatch after transition.

File revision observations and source-projection check manifests are durable integrity-linked artifacts, committed before receipts. Review requires exact subject evidence and actual successful check/receipt bindings. A later observed conflicting revision marks affected checked evidence stale; an approving model cannot override it. Required failed/unknown/stale children keep the parent incomplete. Workspace checks still describe the exact tested projection; they are not an atomic guarantee against a noncooperating editor changing files after the last observation.

Role/task contexts are separate. They receive explicit task scope and typed ledger/dependency evidence, not a shared global transcript. Deterministic compaction retains trusted instructions/task scope and exact artifact/message provenance while omitting untrusted history; it cannot turn file, skill, peer or human-edit text into permission. Unsupported oversized contexts fail explicitly.

Messages have stable IDs, ordered per-sender/recipient sequence, insertion-ordered delivery, bounded pending/total counts (256/1024), deduplication and transactional acknowledgment with optional task completion. Consent is exact to decision hash, recipient, scope, permission epoch and expiry; delivery rechecks it. Revoked/expired decisions can be withheld without pretending delivery. `run status UUID` exposes the graph/actor IDs. `run forward UUID --recipient UUID --scope TEXT --decision TEXT` previews an exact review; `--approve DIGEST` queues that decision with consent. The acknowledgment is explicitly nondurable until the supervisor records it. Queue bound: eight. Forwarding never mints a tool grant or changes the immutable run/task scope. Private controls remain outside ordinary queues and worker mounts.

Hierarchy pause/stop/detach/resume use P2 lifecycle controls. A clean pause releases only observed/drained claims; ambiguous claims require repair/disposition. Resume keeps run/session/task IDs, deadline, steps and aggregate budget, reconstructs context from provenance, and requires fresh grants. Detached execution uses the same bounded temporary core unit and exact review channel. No hidden inference retry, provider fallback, additional scheduler or external service was introduced.

## Actual validation

- Exhaustive small composition cases, specialist count preservation, invalid parent/dependency cycles, claims/fences, overlapping writers, Git leases, expired claims, reviewer failure and provenance-preserving compaction pass.
- 1000 deterministic scheduler quanta across ten seeds pass FIFO/round-robin fairness and stale-token checks. Every runnable parent is served within three quanta in the declared three-parent fixture; no required child is silently omitted.
- Ledger tests pass stable-message deduplication, altered/gapped messages, exact consent, consent revocation at delivery, withholding, stale permission reservation refusal and atomic acknowledgment rollback. Injected task-update failure leaves both the message and task unchanged, including received-evidence references.
- Contained CLI plan/template previews are model-free, reject links/changed approval and do not create state. A live synthetic Pair plus actual private CLI forwarding delivers one exact consented decision once, acknowledges both routed messages and creates zero tool grants.
- Native synthetic Pair, Crew and Fleet run distinct contexts through reviewed source creation and an actual isolated Python check. Crew/Fleet include a separate Reviewer source read and strict evidence-bound review; coordinators receive references/progress without the source transcript. Required messages are acknowledged and all reservations settle.
- Additional native cases reject technical review and introduce a human edit after the successful check. Neither run completes; the human edit remains unchanged. Native worker/Git/MCP/Solo/recovery/restore/detach qualifications continue passing.
- Adding evidence artifacts changed a prior exact audit-order assertion; the test now requires both diff and observation links before the receipt. Ordinary compile/fixture errors were fixed and rerun. No unavailable Rustfmt/Clippy check is claimed. Dependency graph remains unchanged; bundled SQLite is 3.54.1.
