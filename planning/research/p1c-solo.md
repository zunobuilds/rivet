## Implemented bounded flow

`rivet chat --task TEXT` reads only the explicitly selected project config and requires its provider. The first profile is `llama.cpp-compatible`, with an exact endpoint ending in `/v1/chat/completions` and an explicit model string. There is no selected default endpoint/model, runtime discovery, acquisition or provider fallback. A missing provider fails before state creation. Plaintext transport is limited to literal loopback addresses; remote destinations require HTTPS plus positive run/request spend ceilings. Every inference request receives exact destination/model/data review and a digest-bound single-use broker permit. Each file/process/Git proposal receives a separate exact review and grant. The terminal requires `approve <review-digest>`; queued generic `approve` input cannot authorize an unseen request.

The adapter uses pinned reqwest 0.13.5 / rustls 0.23.46 with the selected features, explicitly initializes ring, disables proxy discovery, redirects, automatic retries and verbose connections. It parses streamed SSE across HTTP/UTF-8 fragmentation, normalizes text/argument deltas and complete proposals, usage and finish/error events. Calls are not complete until the entire response validates. Duplicate JSON keys, call IDs, incomplete/malformed arguments, unsupported stops, EOF and quotas fail explicitly; no partial call can dispatch. There is a 1 MiB total response limit, 64 KiB frame/text/argument limits, 8-call limit and bounded queues. Cancellation, permission revocation and grant expiry bypass those queues. A possibly sent failed/cancelled request is uncertain, never retried automatically.

Compatibility correction: reqwest 0.13's selected TLS feature uses the platform verifier by default, which would discover native host trust paths. Promote already-resolved `webpki-root-certs =1.0.11` as an exact direct dependency and pass its compiled Mozilla certificate set to `tls_certs_only`; no global certificate/environment discovery or weakened certificate verification. Its registry license is CDLA-Permissive-2.0. This is a narrow containment correction, not a different HTTP/TLS architecture. HTTPS endpoint admission is tested; no live remote or full HTTPS server conformance test is claimed here. No keyring backend is qualified or used, and authenticated profiles are not claimed at this milestone.

The Solo loop shares the existing supervisor, broker, registry and ledger. It reconstructs trusted actor/task/descriptor/resource bindings, presents exact typed tool scope for review, then records intent and observed receipts through the same dispatch path. Models cannot mint grants or change the task. Step/deadline limits bound both inference and tool steps. Context is an explicit 32 KiB message budget containing the user task and bounded untrusted evidence/results; there is no ambient repository scan, hidden truncation, automatic summarization or transcript persistence. Unsupported context size stops safely. Process checks reference SHA-256 of their exact immutable source projection in both result and receipt/report, distinguishing tested input from a model's completion text.

Schema v2 adds run budget limits and inference reservations to the same database. Reservation commits before send; aggregate token/request/cost admission is transactional. Input admission uses a conservative byte estimate, not an asserted tokenizer. Observed valid usage settles tokens; missing/excess/uncertain usage retains the reservation and blocks session continuation for recovery. Costs are conservatively charged at the explicitly approved per-request upper bound, not an invented provider price or a guarantee about external billing. No monetary estimate is preselected. Existing v1 state is backed up under its retained exclusive lock before migration using SQLite's backup API, quick_check, schema verification and file/directory sync; migration and audit commit together. Read-only inspection does not migrate or create a backup.

`chat --session UUID --task TEXT` starts a new bounded run in the existing session using redacted operation/revision references, not raw transcripts or automatic replay. Pending/unknown/cancelled effects and uncertain inference reservations refuse continuation until recovery. `project new NAME` previews the fixed source-only Rust binary recipe and digest; `project new NAME --approve DIGEST` creates new files only after exact review. It neither installs dependencies nor builds/runs the template; existing projects and invalid paths are preserved/refused.
