# P2b bounded lifecycle qualification

30 October 2026. Prerequisite P2a is committed as `354cf6c`. The [bounded qualification contract](../P2_P3_QUALIFICATION.md) governs this milestone; no mandatory elapsed soak remains. Optional multi-day endurance is deferred to P7. No multi-day, power-loss or general-host qualification is claimed.

## Implemented

Schema 5 persists a versioned immutable RunSpec, explicit lifecycle state, consumed steps, wall/remaining monotonic deadline bound and typed checkpoints in the same writer/ledger. The initial task is retained privately for explicit continuation; raw model/tool transcripts remain off. Each inference/tool step is durably consumed before admission. A wall rollback blocks work; forward/suspend-like jumps and monotonic exhaustion expire it. Larger subsequent clock allowances cannot extend the original bound.

`run status UUID` reports quiescent durable state or the active supervisor's snapshot/pending review. `run pause UUID`, `run stop UUID` and `run disconnect UUID` use a private owner/nonce-bound Unix socket, separate from provider and ledger queues. An acknowledgment means cancellation requested, explicitly **not** durable completion or a reaped-child claim. The same supervisor cancels and drains approved workers, revokes grants, records a safe checkpoint and pauses/stops. Unknown effects/usage remain visible and block continuation/completion. Ctrl-C now awaits this path instead of dropping the running CLI future.

`run resume UUID` previews the exact durable snapshot; `--approve DIGEST` performs a versioned transition with a fresh permission epoch. Old scopes/grants never revive. It preserves the original task, session/run IDs, deadline, steps and aggregate budget, while reconstructing context from redacted evidence. Every new inference/tool request still requires exact review. Uncertain inference needs explicit acknowledgment, without refund/resend; uncertain effects need explicit disposition. Stopped/completed/expired/exhausted runs cannot resume. Remote continuation requires an explicit positive `--request-cost-micros`; it does not increase the stored ceiling. Ephemeral credentials must be supplied again after restart; no keyring or plaintext fallback exists.

`chat --detach` and approved `run resume --detach` explicitly start the **same binary/supervisor** in a bounded temporary user systemd unit. No second scheduler or daemon is introduced. The core verifies actual cgroup CPU 100%, memory 512 MiB, swap zero and PID limit 64 before admission; the unit also has a 3610-second outer lifetime bound. All untrusted workers retain their stricter independent runtime containment. Private UUID/nonce ownership is synced before launch. Core logs stay private inside state. The private control channel shows exact pending review; `run approve UUID CHALLENGE` approves that one challenge once. Polling/reconnecting grants nothing. Explicit detached disconnect preserves the current policy; ordinary terminal EOF pauses. Detached ephemeral-stdin keys are unsupported because systemd must not receive credentials through argv, environment or persisted input. Native credential use remains foreground only.

## Actual qualification

- Contained offline all-target check/tests pass; native tests pass against synthetic loopback providers. No live inference was used.
- Seeded stress: 1000 synthetic supervisor dispatches across ten seeds, 100 pause/resume cycles and ten clean checkpoint/restart cycles. Queue capacities/yields/control positions vary deterministically. All consumed requests/tokens/cost are bounded and charged; paused work cannot reserve more; no grants remain. Per-seed timeout is 30 seconds. The measured initial full matrix took 16.993 seconds; this is a short synthetic test, not an endurance/model benchmark.
- Ten additional actual process exits with a reserved inference request: explicit recovery retains usage, resume stays denied until exact disposition, and duplicate request IDs cannot resend. P2a's repeated effect, migration, recovery, blob and restore matrices continue passing after migration to schema 5.
- 100 separate private-channel approval/control interleavings across ten seeds: wrong/duplicate challenges denied, detached disconnect obeyed, pause/stop acknowledged. A measured full-suite maximum acknowledgment was 290 microseconds, below the 250 ms target on this host. A deliberately held ledger writer plus a completely saturated 128-command queue does not delay the control acknowledgment. Acknowledgment latency does not imply immediate effect cancellation.
- Injected clocks cover rollback, forward/suspend-like expiry, monotonic exhaustion and attempted time extension. Existing provider tests cover EOF, missing usage, malformed streams, timeout/cancellation, quota/redirect refusal and no retry/fallback. Existing broker tests cover expiry, revocation, scope and epoch substitution. Native forked workers, output floods, revocation, recovery and restore cleanup continue passing.
- Integrated Solo disconnect occurs before send (no HTTP request); exact resume retains task/deadline/limits and advances the version/epoch. A detached native core waits for review, survives explicitly permitted disconnect, pauses/drains, reconnects to the same run, demands a fresh challenge, executes one synthetic request, completes and leaves both temporary units collected. No leaked owned unit was observed.
- During development, a deferred SQLite-write fixture failed immediately with busy instead of blocking; it was replaced by an explicit test-only writer barrier and actual queue saturation. Schema-gate/fixture migration mismatches and ordinary compile errors were corrected and rerun. No failed check is represented as a pass.

## Limits and next work

Initial limits remain 100 total inference/tool steps and one hour; this does not implement unlimited retries or unattended permission minting. Current UI requires exact review for every new request, including detached operation. No live online backup, real keyring, actual reboot/suspend/clock change, model/runtime acquisition, installation, paid call or push occurred. Rustfmt/Clippy remain unavailable; no install. Dependency graph is unchanged (227 checksum-verified sources, bundled SQLite 3.54.1). P3 modes, graph scheduling, messaging and model policies are the next dependent stage and are not provided by this milestone.
