# P2a bounded recovery and restore qualification

30 October 2026. This supersedes the incomplete status in [the earlier checkpoint](p2a-checkpoint.md). The [owner-approved bounded qualification contract](../P2_P3_QUALIFICATION.md) replaces the old mandatory endurance gate. This is process-crash and fault-injection evidence on the current Linux host, not host power-loss, reboot or multi-day qualification.

## Implemented behavior

Schema 4 adds explicit recovery dispositions. `repair reconcile --operation UUID` previews typed intent and descriptor-safe current revisions. `--decision accept-observed-post --approve DIGEST` acknowledges matching observed content without claiming causation; `abandon-unknown` records explicit abandonment. A changed observation invalidates approval. Neither path replays a tool, command or Git operation. Unknown inference acknowledgment (`repair acknowledge --request UUID --approve REQUEST_DIGEST`) keeps its reservation charged and never resends it. Continuation retains recovery provenance without raw file content or invented receipts. Recovered or previous-owner runs cannot admit fresh effects or inference reservations.

Backups now include a standalone SQLite image and a private `.assets` directory with an integrity manifest and every referenced blob. Verified pre-migration backups use the same bundle. `repair restore --backup NAME` previews an exact source/backup/identity/worker-bound review. Passing `--approve DIGEST` stages a separately locked private state directory, copies verified assets, migrates supported schemas, revokes all restored grants and fences by a fresh state-directory identity and epoch. Restored old-run budgets are exhausted conservatively; no rollback creates free quota. Old runs pause, uncertain usage/effects remain explicit and fresh work requires fresh authorization.

Activation exchanges directories atomically while retaining both locks. Durable restore markers block normal admission throughout interruption recovery. The same exact approved token can explicitly finish an interrupted restore. All old UUID/nonce-bound workers are contained before admission. The displaced state, journals, blobs and backup evidence remain under a protected `.rivet-repair-UUID` sibling; archived state cannot reopen as an active ledger. No automatic purge exists. A durable private worker sidecar is synced before launch, independently of the database image, so restoring a backup made before a worker existed still contains that worker. Missing main databases with surviving state are recovery evidence, never automatic initialization.

State accounting includes backups, raw recovery copies, staged allocations and conservatively retained displaced state. New work stops at the initial 512 MiB ceiling. Failed stages/orphans remain charged and preserved. Inspection limits remain bounded (64 MiB per database image/blob, 1024 referenced blobs, 256 MiB referenced blob total); larger states fail explicitly. Backup/restore and repair require exclusive ownership; there is no live online-backup or automatic restore fallback.

## Actual checks

- Contained offline all-target check and unit/integration suite pass. Unit tests include private 8 KiB tmpfs artifact ENOSPC, an actual SQLite maximum-page/full error, transactional audit rollback, corruption, busy ownership, newer schema, protected links/mounts and missing-main refusal. Full storage fixtures never exhaust host disk.
- Two repetitions of six actual child exits at authorization, intent, dispatch, effect, artifact link and receipt; two repetitions of nine migration/recovery/blob activation boundaries; two repetitions of six restore boundaries. Raw journals/displaced state survive and ambiguous effects are never replayed. Recovery faults preserve sticky admission; restore faults either retain the original or require explicit completion.
- Restore rejects changed approval, invalid/newer manifest/database, mismatched project, missing/corrupt/linked assets. A corrupt or missing original main database can be restored only with the retained project/worker evidence and a valid asset bundle. Existing human edits invalidate observed-effect reconciliation.
- Native worker tests exercise actual delegated CPU/memory/PID controls, namespace/Landlock restrictions, revocation/cancellation and process cleanup. A core is killed while its approved forked worker lives; both recovery and restore stop the exact old unit before admission. A delayed service refuses execution after revocation. Other native fixtures cover Git, MCP and synthetic Solo.
- Actual build-script/child filesystem/environment/network containment check passes. Rustfmt and Clippy commands both return 101, unavailable in the contained installed toolchain; no installation or claim of those checks passing.
- No dependency changes/acquisition: 227 registry source archives match lockfile SHA-256 values; declared licenses/features checked with `scripts/audit-dependencies.py`. Rust 1.99.1; rusqlite 0.41.1 / libsqlite3-sys 0.39.1; bundled SQLite 3.54.1. Existing license/provenance and platform limits remain; this is not vulnerability clearance.
