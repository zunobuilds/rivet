## Provider, browser and tool choices

The first production provider profile is **llama.cpp-compatible Chat Completions** against an explicitly configured existing endpoint. This is an implementation order, **not a preselected runtime, endpoint, model, acquisition or cloud fallback**. Default configuration has provider unset. Implement streamed content/tool calls, complete argument assembly, usage/stop reasons and explicit unsupported-capability errors. Keep cancellation/usage uncertainty visible. No Responses/hosted-agent dependency is needed for this first profile. Add native Ollama and hosted Anthropic adapters after the first Solo flow, preserving the same interface and separate data/cost grants. [Server API, S23](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

For P1c, loopback HTTP is allowed only for the exact configured address/port under a run grant; remote endpoints require HTTPS and destination/data approval. Disable implicit proxy discovery, redirects, automatic status-code retries and verbose HTTP/SSL key logging. Retry a possibly sent inference request only after reconciliation/explicit policy, since charging or work may already have occurred. There is no credentials/model requirement for administration. [Client controls, S60](https://docs.rs/reqwest/0.13.5/reqwest/struct.ClientBuilder.html)

Choose **Node.js 24.22.2 LTS + JavaScript Playwright 1.64.1 + its matching Chromium revision** for P4a. No TypeScript compiler or permanent JS service is needed: a bounded stdio worker uses the official library; separate fixture tests can use the upstream test runner. Published Playwright requires Node >=20 and matching playwright-core 1.64.1, so this is a documented runtime fit, not a successful browser test. Python remains a documented rejected-for-default alternative; uv is retained for actual Python tools. Node has MIT licensing with third-party notices; Playwright is Apache-2.0, browser notices separate. [Release support and metadata, S61](research/source-register.md)

Choose bubblewrap 0.13.1 as the Linux external-worker boundary, Landlock as a probed additional layer and a deny-network baseline. Do not silently use setuid/system installation or `--no-sandbox`. Provider traffic originates in the trusted provider adapter; untrusted build commands get no network. Later granted general egress uses one policy-controlled proxy; raw device/network permissions remain separate. cgroups require delegated controllers; missing required enforcement denies that worker profile. Do not replace this with gVisor/VM without a scoped demonstrated need. [Sandbox limitations, S29](https://github.com/containers/bubblewrap), [strict versus best-effort Landlock, S62](https://docs.rs/landlock/latest/landlock/)

Use native AT-SPI tree inspection and ashpd portal sessions in the dedicated Linux worker, with separate app/tree/screen/input/clipboard grants. Start qualification on Ubuntu 24.04 LTS x86_64 GNOME Wayland and Fedora 44 x86_64 KDE Wayland as **proposed test targets**, not verified support; include GTK and Qt native fixtures. X11 is an explicit later matrix entry. A broad desktop grant cannot enforce “only one app” by itself: reject unsafe input when target/focus is uncertain. [AT-SPI, S36](https://docs.gtk.org/atspi2/), [ashpd, S63](https://docs.rs/ashpd/latest/ashpd/)

Acquisition: keep aqua 2.65.2 for selected CLI artifacts and uv 0.13.6 for Python tools; explicit per-tool versions, root-contained paths, verified original upstreams, lazy acquisition off, no PATH fallback. Choose Mike Farah's yq identity for the planned multi-format adapter; its exact release/license qualifies at P6. Preserve every approved specialist family and IDs 1–109 without inventing the missing manifest. No runtime/model weights in any preset. Node/browser and native-session dependencies belong to Recommended/selected capabilities only when authorized. Full remains a qualified broader set, Custom explicit selection, Minimal Solo, Portable recommended, System explicit opt-in, no Hybrid.

## Contract baseline v1

These named contracts and invariants are ready for implementation within their assigned stages, not a published API or code scaffold. Use Serde enums/typed records, not arbitrary string maps or model-generated state transitions. Domain and broker logic must remain testable without network/process execution.

| Contract | Required fields and result |
| --- | --- |
| RunSpec | Schema version, project/session/run IDs, user task, validated mode/roles, provider reference or unset, deadline/step budget, permission epoch; immutable after admission except explicit versioned transition |
| ProviderPort | Capabilities plus infer(request, cancellation) returning ordered TextDelta, ToolCallDelta, ToolCallComplete, Usage, Finish or Error; include request/call IDs; no authority to execute tools |
| ToolDescriptor | Namespaced ID, version/build digest, input schema, output limit, declared effect class, permission categories, platform and cancellation/reconciliation capabilities |
| ToolProposal | Operation/attempt/task/actor IDs, descriptor digest, normalized arguments, resolved resource identities, workspace preconditions, budget reservation |
| BrokerDecision | Deny(reason), Ask(exact scope), or Allow(non-forgeable in-process grant reference); persisted approval references bind proposal digest, epoch and expiry; worker cannot fabricate grants |
| ExecutionReceipt | Stable operation ID, attempt, observed outcome, exit/error, artifacts, before/after revision references and redacted output; unknown is a first-class outcome |
| LedgerCommand | Expected state/revision and owner fencing epoch plus transition/evidence; reply only after transaction commits; errors stop affected dispatch |
| MessageEnvelope | Message ID, causal ID, sender/recipient/task, ordered sequence, evidence and authorized user-decision references; acknowledgment deduplicated transactionally |
| WorkerRPC v1 | JSON-RPC 2.0 over private stdio; handshake/version/capabilities, execute, cancel, progress, receipt; 1 MiB frame ceiling, bounded writes and IDs; no network listener |

Operation progression: proposed → authorized → intent-recorded → dispatched → receipt-recorded → terminal. Crashes after intent but before receipt require reconciliation; cancelled and outcome-unknown cannot be treated as effect-free success. Task terminal states and approvals remain distinct from operation state. The [security crash matrix](security-and-recovery.md) is binding engineering acceptance logic, without promising exactly-once external effects.

Initial SQLite schema v1: meta(schema version, project UUID, next event sequence), sessions(id, created_at, config_version), runs(id, session_id, mode, state, owner_epoch, revision), agents(id, run_id, role), tasks(id, run_id, owner_agent_id, state, revision), operations(id, run_id, task_id, actor_id, descriptor_digest, proposal_digest, state, revision), grants(id, operation_id, epoch, expiry, scope), events(sequence, entity_id, actor, kind, redacted payload). Foreign keys and unique IDs required; transition and corresponding audit event commit together. Add durable budget reservations/usage in P1c when inference starts; expand task dependencies/ownership/messages/checkpoints in P2/P3 migrations only when used. P1a inert tests exercise the single root task, not hierarchy scheduling. Audit ordered by sequence, not wall-clock time.

P1a broker records requests/denials and can issue grants only to a test-only inert tool; no production executable dispatcher. Registry enforces duplicate ID/version rejection. P1a fake-provider driver is test-only and stops at proposals. This yields executable administrative and contract behavior without pretending a coding session exists before P1c.

Ledger defaults: local filesystem only, one retained exclusive lock, WAL, foreign_keys=ON per connection, synchronous=FULL, busy timeout 5 seconds, one bounded 128-command writer queue. Fail closed on schema mismatch/lock conflict/disk error. P1a uses explicit initialization and read-only inspection; P2 adds consistent backups, migration restore and power-loss tests. Checkpoint WAL on idle/clean shutdown with bounded effort; report a blocked checkpoint rather than deleting live WAL files. A checkpoint of SQLite pages is distinct from a task execution checkpoint. For standalone P1a status/list, acquire the existing cooperative lock without creating it; if an owner is active report busy, and if WAL/recovery remnants are present report recovery-required without opening the DB. Only a quiescent, verified main DB may be inspected using a read-only immutable URI under that retained lock, preventing WAL/shared-memory creation. Never use immutable mode against a live writer; P2 adds supervised live status/backup. [SQLite URI semantics, S66](https://www.sqlite.org/uri.html)

## Agents, Shared Model and Relay

Approved counts remain: **Solo exactly 1 Independent; Pair exactly 1 Lead + 1 Operator; Crew exactly 1 Lead + 1 Reviewer + Operators >=1; Fleet exactly 1 Director + Leads >=1 + Reviewers >=1 + Operators >=1.** Minimal permits only Solo. Specialists are skills/assignments inside the active composition; creating extra roles needs a permitted mode transition.

Select one task owner and one writer lease for overlapping paths; serialize Git index/ref mutation. Task dependency cycles reject admission. Reviewer results reference exact tested artifacts; review never grants user permissions. One FIFO ready queue per parent with round-robin service between parents, one dispatch quantum per completed provider/tool step; cancellation has a separate control channel. Claims use revision compare-and-set and fencing; expired leases do not prove an old child stopped.

Mesh default: two local peers, with a user-configurable positive peer count and deterministic task claims (queue order, stable agent-ID tie-break), exactly one owner/task, common broker/ledger, supervisor-mediated conflict escalation to main chat. No network cluster or distributed consensus. Adaptive default: select the smallest permitted valid composition satisfying the run's explicit coordination/review-role requirements whose estimated budget fits; if requirements are ambiguous keep the current mode; start with the user-selected mode, change only at a quiescent boundary and within an explicit allowed-mode list and agent ceiling. Without that list, no automatic change. Both are technical policies recommended for P3c approval, not previously approved product semantics.

Shared Model: distinct contexts share a configured resident model/provider pool with one slot by default; increase concurrency only for a qualified endpoint capacity. Count shared weights once per actual instance, per-request KV cache/context separately, plus loading overlap/browser/OS reserve. Model Relay: serial phase reservations and evidence handoffs, not hidden-state copying; loading/unloading requires explicit permission and must complete or reconcile before next activation. Concurrent execution uses the same queue/budgets and never bypasses workspace leases.

Messages use at-least-once delivery with stable deduplication and transactional acknowledgment. Ordinary progress routing follows the run's recipient policy; forwarding important user decisions requires recorded recipient/scope consent. Context keeps trusted instructions separate from file/web/tool/peer evidence, preserves provenance through compaction and never treats human file edits as elevated instructions. Cookbook ingests qualified read-only llmfit JSON and ranks whole-hierarchy allocations under Efficient/Balanced/Ambitious preferences; no automatic benchmarks, model catalog, optimizer service or extra dashboard.

## Security, limits and recovery defaults

The semantic broker is authoritative; Linux sandbox policy enforces grants for untrusted workers. Built-in paths use descriptor-relative operations and no escaping symlinks/mounts; reject unqualified hard links/special files for mutation. Protect state/credentials from model-visible reads and worker mounts. Process argv/cwd/environment/executable identity are part of permission scope; no shell-prefix trust. Git hooks/helpers/filters require explicit execution grants; read-only Git disables unapproved external execution and reports the changed environment. No push capability is implied by local commit permission.

Provider credentials are resolved only by the trusted adapter from explicit ephemeral input or a qualified keyring reference; no discovery of home `.env`, no persisted plaintext fallback, no credentials in logs/argv. Configuration edits cannot approve themselves. Prompt-injection defenses combine provenance, constrained effects and data-egress grants; no detector is claimed to eliminate injection. Remote MCP sampling/elicitation/reverse tool calls cannot silently acquire provider or filesystem authority.

| Control | Recommended default/acceptance target, not a measured result |
| --- | --- |
| Initial run | 60-minute deadline, 100 provider/tool steps, one inference slot; explicit review required for larger/multi-day budgets |
| Model context | Require known or user-declared context limit; reserve response allowance before call; unknown capacity is unsupported, not guessed |
| Currency/quota | Remote inference disabled until user supplies destination/data policy and a positive ceiling; no unlimited default; reserve worst allowed output and uncertain prior usage |
| Output | 64 KiB inline result, 1 MiB RPC frame, 64 MiB per artifact by default; truncation marker plus controlled artifact reference, never silent loss |
| Child stop | UI cancel acknowledged within 250 ms on reference fixture rig; 5-second cooperative grace, then kill owned tree and await reaping up to 2 seconds; report unknown/unreaped on failure |
| HTTP | Connect timeout 10 seconds, idle stream 60 seconds, per-request bound no longer than run deadline; no automatic retry after ambiguous send |
| Shutdown/disconnect | Pause new dispatch and cancel/reconcile on terminal loss initially; explicitly requested detached execution reuses same supervisor executable/ledger under P2b lifecycle approval |
| Long-run qualification | 72-hour deterministic fake-provider soak with scheduled child crashes/restarts and budget/expiry events; live model benchmarking remains separately opt-in |
| Retention | No automatic purge of original evidence, active recovery state or required audit; optional transcripts off by default, opt-in 7-day retention; stop new work at configured state-disk ceiling, initially 512 MiB |

Durable recovery: commit intent before dispatch, stage/hash/fsync/rename artifacts on one filesystem, reference only durable artifacts, backup before migration, reject newer schemas. Resume acquires lock, fences prior owner, contains old child identities, validates artifacts/workspace preconditions, reconciles every ambiguous effect, recomputes budgets/expiry, and resumes only still-authorized work. Permission revocation cannot undo completed external effects. Use UUID operation identities and per-attempt IDs; use upstream idempotency keys only when the endpoint actually supports them. Unknown work blocks affected task completion rather than blind retry.

For shared immutable assets, pin tool content while in use; allow activation only when old users drain, retain rollback and notices, record derivative lineage without altering original evidence. Default acquisition trust: original upstream + HTTPS + independently trusted digest/provenance where available; if an upstream has no trustworthy digest/signature channel, show the reduced assurance and require a tool-specific owner decision instead of claiming authenticity. For Rivet-owned release metadata, reuse existing signature/attestation tooling under owner-managed keys and explicit version/expiry policy; TUF supplies the freshness/rollback reference model. Do not implement another verifier/service or assume every upstream exposes TUF metadata. Signing keys and publication remain owner gates; no fabricated upstream signatures.
